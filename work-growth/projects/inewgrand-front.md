# inewgrand-front

## 项目定位

产业信息平台前台项目，承载用户侧的登录注册、租户开通、应用市场、订单确认、支付凭证、发票信息、产品展示、N-Claw 充值和 Sentry 接入等链路。

## 关键问题

- 前台需要从基础页面推进到可支撑应用市场、租户、订单和支付的完整业务链路。
- 多环境部署涉及 API baseURL、OSS/CDN、图片资源、Sentry 隧道等配置，需要降低环境差异导致的问题。
- N-Claw 充值和支付链路涉及订单创建、二维码展示、跳转、缓存和页面状态，需要保证用户路径顺畅。

## 我的动作

- 搭建和完善登录、注册、忘记密码、租户开通、租户切换、用户下拉、管理入口等基础能力。
- 建设应用市场、应用详情、购买/订阅/免费试用、订单确认、订单详情、上传凭证、发票信息等业务链路。
- 优化验证码、SM2 加密、React Query 状态管理、请求配置、金额格式化、SmartImage、OSS/CDN、动态 API baseURL。
- 接入和修复 Sentry 配置、环境变量、隧道和日志/错误处理。
- 新增 N-Claw 积分充值 iframe、订单创建、支付宝支付二维码、二维码缓存和页面跳转逻辑。

## 结果与提效

- 前台从页面雏形推进到支持应用购买、订单、支付、凭证和 N-Claw 充值的主链路。
- 请求配置、环境变量、OSS/CDN 和 SmartImage 降低多环境资源和接口适配成本。
- N-Claw 充值组件拆分后，后续支付或积分能力维护边界更清晰。
- 实际转化率、支付成功率和排查耗时改善需要补充业务数据。

## 可复用经验

- 交易类前台链路要把“下单、支付、状态、凭证、错误处理、跳转”作为一条完整路径设计，不宜只看单页面功能。
- 多环境配置必须收敛到明确的环境变量和运行时规则，避免在业务组件里散落判断。
- 对图片、上传、金额、验证码等高复用能力应优先组件化或工具化。
